## 1. 产品定位

面向零食电商售前咨询、商品推荐、优惠活动、物流查询和售后退换等高频客服场景，设计 AI 客服工作台与评测系统，提升咨询响应效率，降低商家重复客服成本。

本项目不是单一聊天机器人，而是一套覆盖「客服接待 - 业务数据维护 - 运营标注 - 评测回归 - 上线判断」的 AI 客服产品闭环。

## 2. 项目背景

零食电商客服存在三类典型问题：

| 问题 | 表现 | 影响 |
|---|---|---|
| 高频重复咨询多 | 商品口味、规格、活动、物流、售后问题反复出现 | 人工客服响应压力大 |
| 业务信息变化快 | 商品、优惠券、活动规则会持续更新 | 容易出现价格或规则回复不一致 |
| AI 效果难判断 | Prompt 或知识库更新后缺少评测依据 | 难以判断是否真的降低客服压力 |

## 3. 核心场景

| 场景 | 用户问题示例 | 系统处理方式 |
|---|---|---|
| 商品咨询 | 这个坚果是什么口味？一袋多少克？ | 查询商品信息，回答口味、规格、价格、库存等问题 |
| 商品推荐 | 办公室下午茶有什么推荐？ | 根据用户需求推荐合适商品 |
| 优惠活动 | 满减怎么用？优惠券能叠加吗？ | 查询活动规则和优惠券信息，说明使用条件 |
| 订单物流 | 我的订单到哪了？ | 查询订单状态和物流信息 |
| 售后退换 | 收到破损了怎么办？ | 根据售后规则给出处理指引 |
| 人工转接 | 我要投诉 / 我要找人工 | 识别复杂或高风险场景，转交人工客服 |

## 4. 产品模块

### 4.1 总控台

汇总模型状态、目录健康、评测摘要、运营问题和最近数据变更，辅助判断当前版本是否适合演示、复核或上线。

### 4.2 AI 客服工作台

承接用户咨询，展示 AI 回复、执行过程和运行记录，便于客服理解 AI 的处理依据，并在必要时人工接管。

### 4.3 商品与知识库管理

维护商品信息、FAQ、活动规则、优惠券和售后政策，支持运营持续更新，避免完全依赖一次性 Prompt。

### 4.4 运营标注与问题复盘

沉淀低分回复、未命中问题、转人工原因和用户反馈，用于优化知识库、Prompt 和对话流程。

### 4.5 评测中心

通过评测用例、批量回归和版本对比，验证 AI 客服在准确性、问题解决率、风险拦截和服务效率上的表现。

## 5. 对话流程

```text
用户提问
  -> 意图识别
  -> 查询商品 / 活动 / 优惠券 / 售后政策
  -> 生成回复
  -> 风险与合规检查
  -> 返回用户或转人工
  -> 记录运行过程
  -> 运营标注与评测回归
```

## 6. 评估体系

| 指标 | 说明 |
|---|---|
| 回答准确率 | AI 回复是否符合商品、活动、订单和售后事实 |
| 问题解决率 | 用户问题是否在 AI 阶段被有效解决 |
| 人工转接率 | 有多少问题需要转给人工处理 |
| 用户满意度 | 用户对 AI 回复质量的反馈 |
| 平均响应时长 | 从用户提问到系统返回结果的耗时 |
| 未命中问题数 | AI 无法理解或无法回答的问题数量 |
| 重复问题承接率 | 高频标准问题中由 AI 成功处理的比例 |

## 7. 数据飞轮

```text
用户咨询
  -> AI 回复
  -> 用户反馈 / 人工评分
  -> 识别未命中问题与转人工原因
  -> 补充知识库与优化 Prompt
  -> 回归评测
  -> 重新进入客服场景
```

通过这一闭环，系统可以持续吸收真实业务问题，使客服能力逐步贴近商家的实际经营场景。

## 8. 成本优化思路

系统优先让 AI 承接商品咨询、优惠说明、售后政策等高频标准化问题，减少人工客服在重复问题上的时间消耗。对于投诉、复杂售后、金额争议和风险场景，则保留人工客服介入，避免 AI 过度处理高风险问题。

## 9. 项目成果

1. 完成零食电商 AI 客服产品场景拆解。
2. 规划客服工作台、商品目录、运营中心、评测中心和能力配置模块。
3. 设计从用户提问到问题解决的完整对话流程。
4. 整理商品信息、FAQ、活动规则、优惠券和售后政策等知识库结构。
5. 搭建回答准确率、问题解决率、人工转接率、用户满意度和平均响应时长等评估指标。
6. 输出 GitHub 项目、PRD 文档和演示入口，用于作品集和面试讲解。
